# 已锁定的产品与架构决策

2026-09-19 与用户逐条确认的边界。**改这些等于改产品定义**，要用户点头。

## 定位

- 公开插件：`@duoyu/dsh-inbox`，别人能像装社区插件一样安装；仓库要拿得出手（README、架构图、demo）。
- v1 闭环：**粘贴 → 分类 → 侧栏列表 → 对话里取回原内容**。预览类（视频内嵌等）不做。

## 平台与装配

- 代码跨平台；**v1 只在这台 Windows 验收**，README 明写 mac/Linux 未验证。
- 安装要自动化：装包 + 建 agent preset + 指默认，一条 `init` 完成。
- 开发期 `dsh --profile inbox` 隔离，稳定后叠 patch 进 web profile。

## 入口

- v1：inbox 面板粘贴/拖拽 + 聊天框前缀转存。
- 不做全局剪贴板监听；手机分享进二期。

## 存储与同步

- 本地为准：**走 dsh 自己的存储域 `dsh_inbox`**（`ctx.storageDomain`，JSON 后端），不自己开文件或 SQLite——2026-09-19 修正，此前这条写的是"自建 SQLite"，与实现和 `AGENTS.md` 第 10 条都矛盾。导出/备份仍留作兜底。
- WebDAV 走**单向摄取**（远端 `inbox/` 目录 → PC 启动拉取 → 分类入库）进 v1；双向同步二期。
- 上云只有密文；**主密码永不上传**，初始化生成恢复码让用户抄下来。
- 附件必须随同步包一起走。
- **不依赖 WebDAV 自定义属性（PROPPATCH）**——手机端文件管理器不会实现它；用目录约定 + sidecar 元数据。
- 远端是**两条协议同一件事**：WebDAV 与 S3 共用一条摄取链路，都只读、单向。数据胶囊已实测通过（S3 与 WebDAV 指向同一份存储）；其网关**按 `User-Agent` 认客户端**，AccessKey 绑在哪个"应用"上就得自称哪个应用——标识因此是设置项、且**按协议各存一份**。实测矩阵见 `docs/help/remote-gateway-compat.md`。

## 界面形态（2026-09-19 决定，M7）

- **v1 现状**：仓库是主区域的一个面板（`sidebar.panellist` 图标入口 + `main` keyed slot 整页）。
- **M7 定为「B + A」**：
  - **A 主区域管理页**：全屏管理（分页、批量、编辑）。
  - **B 右侧 dock 的一个 tab**（日常）：与对话并排常驻，官方一等扩展点（`ctx.sidebarRightTabs.register` + `sidebar.right.pane.tab`）。
- **否掉「左侧切换」（用户最初的设想）**：左侧会话列表那一格是 `sidebar.workspaces`，**single 坑位且已被官方 ui-workspace 占用**（合同注释原话 "declaring is claiming"），接管等于自己实现会话列表、搜索、workspace 对话框与状态点，且 dsh 一升级我们就要跟。右侧 dock 能给出同样的"和入口一样在侧边"体验，代价小一个数量级。
- **界面先做原型再动手**：四个结构不同的方案放在 `docs/prototype/2026-09-19-inbox-ui.prototype.html`，由用户敲定后再进实现。
- **用户选 A（三栏分诊）**，并要求（2026-09-19）：类目内容用**卡片列表**、**点卡片才在右侧 dock 出详情**（卡片有高亮态）、**卡片外框统一但内容按类别不同**、**图片与视频可放大查看**、**入库设置改弹窗**。v2 原型：`docs/prototype/2026-09-19-inbox-ui-v2.prototype.html`。
- **三种卡片密度都保留，做成用户可切的「列表模式」**（用户 2026-09-19 定）：单列媒体卡 / 双列网格 / 紧凑行，分别适合不同使用习惯。它**不是**开发期的二选一，而是**用户级设置**（跟主题 `fontSize` 同样待遇，重启还在），默认 **单列媒体卡**；三种共用同一份卡片内容模型，切换只换容器，不动数据。
- **图标库用 Lucide**（`lucide-react`，ISC，圆润线性风格）：客户端半边把它当普通依赖打进产物即可，不需要进平台静态模块表；待 spike 验证打包结果。
- **面板与右侧 dock 互斥（2026-09-19 实测修正）**：右侧 dock 属于**会话表面**，而 Inbox 面板本身就是"占满主区域"的那个表面——打开面板时会话表面被卸载，再从面板里调 `sidebarRight.openTab` 会抛 `sidebarRight: no session surface is mounted`。所以**"点卡片、详情出现在右侧 dock"这个形态在面板里做不到**，原先"详情永远在右侧 dock"的设想作废：
  - **面板里**：详情仍是面板内的固定一栏（列表保持密度，详情位置不乱跳）；
  - **对话里**：右侧 dock 挂一个"随手看"的仓库 tab（从 dock 的引导页进入），用于边聊边看，不做编辑。
  两边共用同一份数据与卡片内容模型，但**不是同一个界面同时出现**。

## 隐私红线

- 账密类：加密落盘、列表脱敏、**明文永不进模型上下文**、对话里**永不输出明文**、长期保留。
- 证件照：**2026-09-19 改**——分类时允许把图片发给模型判断（手机拍的证件照比例与普通照片无异，靠宽高判不出来）；对话里仍然只回标记，字节不进对话。只有用户亲口指明才标确定类目，模型判的随时可被用户改掉。
- 链接标题抓取（**2026-09-20 新增**）：抓 `<title>` 是**一次对外 HTTP 请求**——它会把自己"打开过这个链接"和本机 IP 告诉那个站点。因此：只对**本机捕获的 `kind=link`** 发生（WebDAV/S3 拉进来的链接不抓，避免远端塞一条链接就让本机去打内网），走 dsh 的 `ctx.web` seam（只解析并固定公网地址、拒私网、只跟同源跳转、限时限量、不带 cookie），**花费 0 模型 token**，且在粘贴入库之后异步进行、绝不挡粘贴。抓不到就保持原样（名字退回 URL）。
- 模型平时看不到这个库；**只有它调工具查的时候才看**。

## 分类与交互

- 7 个一级类目：灵感/待办、文章、视频音频、图片、证件、密钥、其它。平台与来源做**标签**，不占类目位。
- 规则优先（URL 判平台与媒体类型、正则判密钥、图片走本地启发式）+ DeepSeek API 兜底；没配 key 时降级为纯规则，不阻塞入库。
- **用户描述 = 权威分类**，模型不得覆盖。
- 修正入口：面板改备注/分类为主；粘贴时连描述提交为辅（仅图片/链接可行）；对话里改分类进二期。
- 移动端摄取进来的条目初始状态是"未整理"（v1 就留字段）。
- 文本类必须两步（先入库、再补描述）——纯文本下"哪部分是资源、哪部分是描述"天然分不清。

## 生命周期

- **只有一个进度标记：待看**（2026-09-19 改）。原先的"未读 → 已读"两档作废——它声称知道软件不可能知道的事（你有没有*消化*一条链接），而且让每一条新记录一出生就是"未读"，等于把你自己输入的待办又数回给你。现在：**新记录不带任何标记**，待看由用户自己打（域版本 3，`watchLater?: boolean`）。旧记录不反填。
- **待看是标记，不是标签**：`待看` 这个标签在迁移里被摘掉，避免一件事有两种说法。
- 删除：软删 + 回收站；清空回收站时才真删附件。
- 重复：合并到原记录（更新时间/备注），不当新记录。

## 抓取与检索

- 链接存 URL + 平台 + 标题（`linkTitle`，抓页面 `<title>`）+ 封面；正文快照进路线图（公众号/B 站内容会消失，这是真实风险）。
- 「标题」的实现边界：不解析正文、不跟随跨站跳转、不执行 JS——只读 `<title>`；所以 SPA 站点可能只有站名，这是可接受的（名字退回 URL）。
- v1 只做关键词检索；语义检索等真实数据量再说。规模假设：千级，不超过几万。

## 对话里的返回形态

- 文本：内联原文，默认截断约 1000 字，超出给"面板里查看"入口。
- 图片：内联缩略图（技术上走 `tool.call.toolview` 的 `loadImage`）。
- 链接：标题 + 平台 + 分类 + 原链接。
- 列表：时间倒序 10 条 + "还有 N 条"。
