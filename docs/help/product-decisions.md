# 已锁定的产品与架构决策

2026-09-19 与用户逐条确认的边界。**改这些等于改产品定义**，要用户点头。

## 定位

- 公开插件：`@duoyu/dsh-inbox`，别人能像装社区插件一样安装；仓库要拿得出手（README、架构图、demo）。
- v1 闭环：**粘贴 → 分类 → 侧栏列表 → 对话里取回原内容**。预览类（视频内嵌等）不做。

## 平台与装配

- 代码跨平台；**v1 只在这台 Windows 验收**，README 明写 mac/Linux 未验证。
- 安装要自动化：装包 + 建 agent preset + 指默认，一条 `init` 完成。
- 开发期 `dsh --profile inbox` 隔离，稳定后叠 patch 进 web profile。

## 入口

- v1：inbox 面板粘贴/拖拽 + 聊天框前缀转存。
- 不做全局剪贴板监听；手机分享进二期。

## 存储与同步

- 本地为准（自建 SQLite）；导出/备份是兜底。
- WebDAV 走**单向摄取**（远端 `inbox/` 目录 → PC 启动拉取 → 分类入库）进 v1；双向同步二期。
- 上云只有密文；**主密码永不上传**，初始化生成恢复码让用户抄下来。
- 附件必须随同步包一起走。
- **不依赖 WebDAV 自定义属性（PROPPATCH）**——手机端文件管理器不会实现它；用目录约定 + sidecar 元数据。
- 数据胶囊只是"一个支持 WebDAV 的地方"，设计只绑协议（其 WebDAV 能力由用户侧确认，我方未能独立验证）。

## 隐私红线

- 账密类：加密落盘、列表脱敏、**明文永不进模型上下文**、对话里**永不输出明文**、长期保留。
- 证件照：默认全本地弱启发式判断；只有用户亲口指明才标确定类目。
- 模型平时看不到这个库；**只有它调工具查的时候才看**。

## 分类与交互

- 7 个一级类目：灵感/待办、文章、视频音频、图片、证件、密钥、其它。平台与来源做**标签**，不占类目位。
- 规则优先（URL 判平台与媒体类型、正则判密钥、图片走本地启发式）+ DeepSeek API 兜底；没配 key 时降级为纯规则，不阻塞入库。
- **用户描述 = 权威分类**，模型不得覆盖。
- 修正入口：面板改备注/分类为主；粘贴时连描述提交为辅（仅图片/链接可行）；对话里改分类进二期。
- 移动端摄取进来的条目初始状态是"未整理"（v1 就留字段）。
- 文本类必须两步（先入库、再补描述）——纯文本下"哪部分是资源、哪部分是描述"天然分不清。

## 生命周期

- 状态：未读 → 已读两档；暂不做"归档"。
- 删除：软删 + 回收站；清空回收站时才真删附件。
- 重复：合并到原记录（更新时间/备注），不当新记录。

## 抓取与检索

- 链接存 URL + 平台 + 标题 + 封面 + 一句话摘要；正文快照进路线图（公众号/B 站内容会消失，这是真实风险）。
- v1 只做关键词检索；语义检索等真实数据量再说。规模假设：千级，不超过几万。

## 对话里的返回形态

- 文本：内联原文，默认截断约 1000 字，超出给"面板里查看"入口。
- 图片：内联缩略图（技术上走 `tool.call.toolview` 的 `loadImage`）。
- 链接：标题 + 平台 + 分类 + 原链接。
- 列表：时间倒序 10 条 + "还有 N 条"。
